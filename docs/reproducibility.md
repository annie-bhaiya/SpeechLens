# Reproduction and operational limits

Python 3.11.17 isolated environment, pinned by .python-version; exact resolved transitive versions in uv.lock. Node 24.18.0 was tested with the npm lockfile. The verified Linux container uses Python 3.11.13: two fresh container runs produced identical events/scores on the demo pair (evaluation/docker_check.json). This does not establish broad Windows/Linux numeric equivalence. CPU is the tested execution path; no GPU throughput is asserted. Model revision and SHA-256 weights are pinned in configuration/release metadata. No LLM API, cloud storage or external runtime service is required after dependencies and model caches are prepared. Dashboard fonts have system fallbacks, no runtime font downloads.

Windows: run `./speechlens.ps1 setup`, `./speechlens.ps1 models`, then `./speechlens.ps1 serve`. The bundled dataset already contains WAVs; rebuilding sources requires network. Make targets are equivalent for uv/npm/make environments. `./speechlens.ps1 test` runs meaningful math, detector, ingestion, API and recovery checks; `e2e` requires the live server and `python -m playwright install chromium`.

Private volume defaults to storage/. Set SPEECHLENS_STORAGE to an absolute persistent path if desired. One inference subprocess, at most ten queued/running upload jobs, 100 MB per file, 1-600 seconds, 900-second processing bound. The analysis app remains a trusted local prototype without authentication; the human portal has separate pseudonymous accounts, session hashes and coordinator role checks. Docker Compose binds loopback and declares persistent upload/model volumes. The initialized Docker Desktop Linux engine passed dependency builds, pinned-model download, fresh processing, repeat stability, native range audio, export and deletion on 2026-10-06. The container lock installs the standard Linux PyTorch wheel with CUDA runtime dependencies even though inference is explicitly on CPU; image size is larger than a CPU-only packaging variant.

Artifacts: original files are ignored under data/originals; release WAVs, transcripts, machine alignments, transformation supports and provenance are retained. Upload originals are preserved privately. Delete evaluation removes the full job directory and its private cache. To remove only public research caches, delete .cache after verifying its resolved path; downloaded model weights will need downloading again. Never remove a configured upload volume as routine cleanup.

Numeric stability: repeat-run tests use fresh inference and compare event IDs, intervals, values and displayed scores. Actual output is in evaluation/robustness.json. Different FFT/model builds may introduce small floating differences; numeric portability is not established by a same-machine run. Code/config/audio/transcript changes invalidate caches. Schema validation forbids NaN JSON, invalid clocks and unqualified all-missing scores.
